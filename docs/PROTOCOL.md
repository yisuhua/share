# 原生客户端接收协议 v1

所有请求带 `Authorization: Bearer <电脑面板显示的配对密码>`。不要把密码写入日志、URL 或仓库。

`GET /v1/info` 返回协议版本、接收器名和 max_bytes。未经认证不返回这些字段。

`POST /v1/files?name=<UTF-8 URL 编码的文件名>` 上传原始文件字节，不是 multipart。一次一个文件。

必须提供 Content-Length 和 X-Content-SHA256（原始字节 SHA-256 的64位十六进制）。不支持 chunked。客户端成功条件：收到 201，且 bytes、sha256 与原文件一致。仅请求发送完毕不是成功。

成功：`{"name":"图片.png","bytes":3,"sha256":"..."}`。name 为电脑实际保存名，重名可能加序号。

错误：400 参数/不完整数据；401 配对密码错误；403 非局域网或带 Origin；404 未知接口；408 超时；409 重名数量过多；411 长度缺失或歧义；413 超过大小；422 哈希不一致；507 磁盘/目录错误。

传输中断后由用户明确重试。若文件已经保存但响应丢失，重试可能产生另一个同名副本，当前协议未实现幂等 upload ID/断点续传。

客户端不可请求任意目标路径，目标目录只能在电脑设置。文件内容按字节保存，不进行压缩、格式转换或执行。

## 原生文件表单兼容入口（新增，不替换 raw 接口）

`GET /v1/info` 增加 `form_upload: true`，原有字段与 protocol=1 保持不变。客户端应先检查此能力字段。

`POST /v1/form-files?name=<原始文件名>` 接收一个名为 `file` 的 multipart/form-data 字段。认证、SHA-256 和成功回执与 raw 接口相同；新增 `X-File-Size` 表示原始文件字节数。HTTP Content-Length 表示整个 multipart 请求长度，由原生网络库计算，不可错误设置为原文件长度。

允许的封装头部不超过 4096 字节，总封装额外开销不超过 8192 字节；boundary 长度 1–70 个受限 ASCII 字符。文件体按 X-File-Size 精确读取，不扫描文件内的 boundary 字节；核对唯一结束边界后再校验哈希、刷盘发布。额外 part、错误大小、缺少边界一律拒绝，不留下完成文件。

Multipart 中的 filename 不决定保存路径或保存名，仍由查询参数 name 和电脑目录设置决定；同名保护不变。两个入口使用相同的原文件大小上限，封装开销不挤占原文件限额。不支持 chunked。
